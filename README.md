# 认人本 · astrbot_plugin_identity

让 AstrBot **真正记住谁是谁**，而不是每轮都靠昵称猜。

[![AstrBot](https://img.shields.io/badge/AstrBot-%3E%3D4.9.2-blue)](https://docs.astrbot.app)
[![License](https://img.shields.io/badge/license-AGPL--3.0-green)](LICENSE)

---

## 为什么需要它

QQ 官方号（`qq_official`）的身份信息是残缺的，实测结论如下：

| 场景 | 昵称 | 原因 |
|---|---|---|
| 群聊 | 有（但不保证） | 网关 `author.username`，AstrBot 打过补丁才拿得到 |
| 私聊 | **永远没有** | C2C 协议 `author` 只有 `user_openid` |
| 群成员列表 | **不可用** | 官方标注「内邀接入中」 |
| 跨群同一个人 | **对不上** | 官方：同一 bot 在不同群，`member_openid` 不同 |

结果是：改名就失忆、私聊像陌生人、群里 A 和 B 分不清。

现有的同类插件（昵称映射表、QQ 号识别）几乎都面向 OneBot/aiocqhttp——那个场景下
QQ 号稳定、昵称总能拿到。**本插件面向的是拿不到昵称的场景**，靠被动学习把碎片拼成名册。

## 功能

- **群聊被动学习**：每条群消息顺手记录 `openid → 昵称`，零配置
- **改名留史**：昵称变化只追加别名，主名按来源等级升级，不被覆盖
- **私聊借用映射**：私聊无昵称，但 openid 与群里一致时自动认人
- **脏名过滤**：自动丢弃「昵称等于 openid」「`[At:xxx]`」这类污染值
- **跨群合并**：`/合并` + `/撤销`，破坏性操作可回滚
- **名册注入**：默认只注入本条消息相关的人（发言人 / 被 @ / 正文点名），受字符预算限制；可关掉回到全量名册
- **手写备注**：`/备注` 给某人写一句话（如「服务器主人，爱考 MC 知识」），随名册注入
- **短别名**：`/别名` 给长昵称的人设个 1~12 字的短名，名册注入与指令寻址都用它
- **可查**：`/名单` 分页看全部人，`/曾用名` 看某人的改名时间线
- **可备份**：`/导出` 写成 JSON，`/导入` 在另一台实例合并回来
- **数据删除权**：`/忘记` 彻底删除某人记录

## 平台差异

不同适配器能提供的身份信息差别很大（以下按源码核对）：

| 平台 | 群昵称 | 私聊昵称 | 群名 | 状态 |
|---|---|---|---|---|
| `qq_official` | 有（网关 `author.username`，不保证） | **没有** | 拿不到 | 实测中 |
| `aiocqhttp` | 有（群名片优先，其次昵称） | **有** | 拿不到，需 `/群名` | 源码核对，**未实测、未声明支持** |

> `support_platforms` 目前只声明了 `qq_official`。aiocqhttp 按源码核对应该可直接使用，
> 但尚未在真实 OneBot 连接上验证，所以不写入声明，避免给人“已测”的错觉。
> 如果你在 aiocqhttp 上跑通了（`/我是谁` `/群名` `/谁` 均正常），
> 欢迎提 PR 把 `metadata.yaml` 里那行注释取消。

两个适配器的坑：

- aiocqhttp 在 sender 既无群名片也无昵称时会填 `N/A`，其请求/通知事件则把昵称填成 QQ 号；
  本插件会把这两类值当脏数据丢弃（有测试覆盖）。
- 私聊昵称只在 QQ 官方号上不存在，所以「借用群聊映射」主要服务于它；aiocqhttp 私聊本来就有名字，
  本插件在那里的价值是改名历史、跨群合并、备注和名册注入。

## 安装

### 插件市场

AstrBot WebUI → 插件 → 插件市场 → 搜索「认人本」或 `identity`。

### 手动

```bash
cd AstrBot/data/plugins
git clone https://github.com/yunfang1718128/astrbot_plugin_identity
```

重启 AstrBot（或 WebUI 内重载插件）后生效。**无第三方依赖**。

## 指令

| 指令 | 权限 | 说明 |
|---|---|---|
| `/我是谁` | 所有人 | 查看自己的短码与已识别身份 |
| `/我是 <名字>` | 管理员 | 私聊认领身份；可写作 `/我是 <群名或短码> <名字>` |
| `/群名 <中文名>` | 管理员 | 在群里给本群起名，供私聊寻址 |
| `/群列表` | 管理员 | 已知群 + 各自认识多少人 |
| `/谁 <名字/短码/#编号>` | 管理员 | 查身份卡 |
| `/合并 <A> <B>` | 管理员 | 把两个身份合并成一个人 |
| `/备注 <名字> [内容]` | 管理员 | 查看/设置/清空一句话备注；省略内容=查看，`-`=清空 |
| `/别名 <名字> [短名]` | 管理员 | 设/查/清短别名；省略短名=查看，`-`=清空，不带参数=列出全部 |
| `/名单 [页码]` | 管理员 | 分页列出身份库，每页 10 人 |
| `/曾用名 <名字/短码/#编号>` | 管理员 | 看某人的名字时间线（来源/时间） |
| `/导出` | 管理员 | 导出整库到插件数据目录的 JSON 文件 |
| `/导入 <文件名>` | 管理员 | 从数据目录里的导出文件合并导入 |
| `/撤销` | 管理员 | 回滚最近一次合并 |
| `/忘记 <名字/短码/#编号>` | 管理员 | 彻底删除某人记录 |

> **群短码** = `group_openid` 前 8 位，永远可用；中文群名需要管理员先 `/群名` 命名。

### 典型用法

```text
# 1. 在群里给群起名（一次即可）
/群名 摸鱼群

# 2. 私聊里认领「我是某个群的某人」
/我是 摸鱼群 云帆少年

# 3. 同一个人在两个群，openid 不同 → 手动合并
/合并 云帆少年 云帆（另一个群）
/撤销                    # 合错了随时回滚

# 4. 昵称太长（如「✨云帆少年✨考研版」）→ 设个短别名
/别名 #3 云帆           # 之后名册、/谁、/备注、/合并 都可用「云帆」
/别名                   # 看全部已设别名
/别名 云帆 -            # 清掉别名，恢复用原名

# 5. 查与备份
/名单                   # 身份库第一页，/名单 2 翻页
/曾用名 云帆            # 这个名字用过哪些名字、什么时候
/导出                   # 返回文件路径，用 scp 取回
/导入 identity-export-20261019-003000.json   # 在另一台实例恢复
```

## 配置

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关，关闭后不学习也不注入 |
| `inject_enabled` | `true` | 是否把名册注入 system prompt |
| `slim_inject` | `true` | 只注入本条消息相关的人；关掉=注入最近 `roster_max` 人 |
| `roster_char_budget` | `240` | 瘦身模式的字符预算，超了截断 |
| `roster_max` | `20` | 全量名册模式的人数上限 |
| `roster_days` | `30` | 多久没说话就不算活跃 |
| `note_inject_enabled` | `true` | 备注是否随名册注入 system prompt |
| `placeholder_prefix` | `群友-` | 无名字时的占位前缀 |
| `protected_ids` | `[]` | 不记录名单（openid），命中者完全不参与 |

## 工作原理

```
群消息 ──► sender.nickname ──► 脏名过滤 ──► 来源等级比较
                                              │
                                              ▼
                                    identity.db ──► 名册注入 system prompt
                                       │
                                       └──► /谁 /合并 /忘记
```

数据模型三张核心表：

- `identities`：一个「人」，含主名、别名、备注与名字来源等级
- `accounts`：`(platform, scope, openid)` → 人。一个可挂多个账号（跨群/私聊）
- `name_history`：见过的每个名字，含来源与首末次时间

显示与注入用哪个名字：**有别名用别名，没别名用主名**。别名是独立字段，
不会被昵称学习覆盖，也不写进 `name_history`（否则会变成一条假「曾用名」）。

名字来源等级（高等级才替换主名）：

`占位(0)` < `平台昵称(1)` < `LLM 抽取(2)` < `用户自报(3)` < `管理员指定(4)`

注入选人规则（`slim_inject: true` 时）：

1. 当前发言人（标「当前发言人」）
2. 本条消息 @ 到的人（QQ 官方号 `At.qq` 就是 openid）
3. 正文里点名的已知成员（别名/主名/曾用名命中，单字名不参与）
4. 以上合计超过 `roster_char_budget` 就截断，并注明「共认识 N 人」

## 隐私

- **只存** `openid`、昵称、备注、首次/最近出现时间；**不存聊天内容**
- 数据位置：`data/plugin_data/astrbot_plugin_identity/identity.db`
- 随时可用 `/忘记` 删除某人全部记录
- 可用 `protected_ids` 让指定用户完全不被记录
- 卸载插件后删除该 `.db` 文件即彻底清空
- ⚠️ **`/导出` 的 JSON 含 openid**，属于敏感数据：不要提交到仓库、不要发到群里，
  用完及时删除（备份位置：`data/plugin_data/astrbot_plugin_identity/identity-export-*.json`）
- ⚠️ **备注会被注入给模型**，模型可能把内容说出来。不要写密码、地址、真实姓名等敏感信息；
  不想要这个行为就把 `note_inject_enabled` 关掉。

## 已知限制

- **跨群自动关联做不到**：官方 `member_openid` 每群不同，只能人工 `/合并`
- **私聊昵称永远没有**：只能靠群聊学到的映射，或管理员 `/我是` 指定
- **群名需要手动命名**：平台不给群名，`/群名` 是唯一途径
- 名册注入追加在 system prompt **末尾**，前面的稳定前缀仍能命中 prompt cache；
  但瘦身模式的尾巴每条消息不同，那一段每次重算。人多、且想要稳定缓存时，
  可以关掉 `slim_inject` 换回全量名册（尾巴稳定，代价是每条都带 300~500 tokens）
- 名字来源等级为「平台昵称」时不保证准确——用户可以把群名片改成任何人，
  这也是为什么提供管理员级别覆盖
